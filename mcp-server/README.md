# 家庭管理 MCP

通过 Hermes 微信对话操作现有家庭管理 REST 接口的独立 stdio 服务。Python 3.11+，不修改后端、桌面端或业务数据库结构，不新增公网端口。

## 工具

| 工具 | 行为 |
|---|---|
| `get_family_context` | 返回北京时间日期、绑定成员、当前家庭成员列表 |
| `add_transaction` | 新增人民币收入或支出，默认支出和服务端默认成员 |
| `list_transactions` | 查询最多31天（含首尾）的全家收支明细、收入、支出及结余 |
| `create_daily_task` | 创建单次或每日重复任务，使用服务端默认成员；仅保存任务，不设置微信提醒 |
| `list_daily_tasks` | 查询最多42天（含首尾）的任务，可按成员和完成状态筛选 |
| `complete_daily_task` | 完成或取消完成指定日期的任务；后端校验任务成员权限 |
| `delete_daily_task` | 删除明确选定的整个任务；重复任务删除前须说明影响并确认 |
| `delete_expense` | 核对日期、记录ID和支出类型后删除一笔支出；不用于收入 |
| `list_courses` | 查询成员本周课表，默认服务端成员；用于定位课程ID、星期和时间 |
| `record_course_attendance` | 记录某天已上课（ATTENDED）或已请假（LEAVE） |
| `list_course_records` | 分页查询课程记录，可按成员、课程名、状态和月份筛选 |
| `list_passbooks` | 只读查询当前家庭存折，支持成员、存款日期、分页与排序，返回全量合计 |

所有日期使用 `YYYY-MM-DD`，时间使用北京时间 `HH:MM`，金额使用最多两位小数的字符串。先获取当前日期和成员，金额缺失、操作意图不明确或任务存在多个匹配时追问。

新增收入/支出可分别填写可选的 `bank_card`（银行卡/付款账户类别）和 `platform`（消费平台），映射到后端 `bankCard`、`platform`。银行卡选项：工商、农业、交通、光大、招商、支付宝、微信；消费平台选项：支付宝、微信、京东、美团、拼多多、淘宝、抖音。未说明时留空，不收集完整卡号、不根据平台猜付款账户。例如“美团买菜50元，用招商支付”填写银行卡招商、平台美团；“工资8000元到账工商”只填写银行卡工商即可。

两个字段均不填时保持原有请求内容和防重编号兼容；填写后会参与请求内容校验，相同编号改变银行卡或平台会被拒绝。收支查询会展示后端返回的这两个字段；本次没有新增按银行卡/平台筛选的MCP参数。

后端创建任务不返回 ID；回执仅返回已保存的字段。后续打卡必须先查询，不能编造 ID。查询账目按月读取全部分页后筛选日期，超过上限或分页不完整时报错，不输出部分统计。

删除前先查询并核对标题、成员和日期，多个匹配须让用户选择。删除每日重复任务会让整个任务定义不再显示，包括历史和未来日期；本版不支持只跳过或删除重复任务的某一天。删除沿用原后端权限和持久化防重，只有收到 `status=deleted` 才回复已删除。删除工具使用 MCP `destructiveHint=true` 标注。

删除支出须先查询并核对金额、日期、分类及成员，再使用记录ID调用；多个匹配先让用户选择。工具会再次验证该日期的记录是 `EXPENSE`，拒绝删除收入或日期不匹配的记录，复用后端对象权限和持久化防重。首次检查失败不会阻塞纠正后重试；成功后的重复请求返回原回执，不因已删除而再次报找不到。

### 课程记录

示例：“今天钢琴课已上课”“昨天英语课请假了”“查一下本月钢琴上课记录”。课程默认成员单独使用 `FAMILY_COURSE_DEFAULT_MEMBER_ID`（当前配置为han），未配置时才回退到通用默认成员。支出和任务仍默认zc；明确提到其他家庭成员时先查询成员，再按该成员的课表选课。多个同名课程须按成员与时间选择，不根据课程名猜编号，也不自动新增课程。

先查 `list_courses` 获取本周课程安排；返回的 `status` 仅代表本周对应课次，补记过去日期时不能套用本周状态，应另查课程记录。`record_course_attendance` 使用查到的课程ID及明确日期，校验当前家庭课程存在、星期匹配、日期不晚于北京时间今天、备注不超过500字。现有后端不支持未来请假，例如“明天钢琴请假”应回复尚不能提前记录，不能偷改为今天。

同一课程与日期会更新已有状态和备注，不另增第二条课次；用户更改已有状态时须说明并确认。后端事务负责课时：已配置该成员/科目余额时，首次上课扣1、请假不扣、上课改请假返还1；MCP不另行扣减，不自行设置余额。保存接口无剩余课时回执，不能编造具体余额；历史查询里附带的余额是当前值，不是历史当日快照。

历史记录每页20条，工具返回 `page`、`page_size`、`total` 和 `has_more`；有后续页时不能把一页当全部记录或据此统计全部上课次数。课程名称过滤为完整名称，月份 `YYYY-MM`，状态只支持 `ATTENDED`、`LEAVE`。本版不支持MCP新增/删除课程定义、编辑课时余额或未来请假。

## 使用边界

### 存折仅查询

示例：“查一下全家的存折”“查一下zc的存折”“按到期日期从近到远列出存折”。默认当前绑定家庭全部成员，不套用记账zc或课程han的默认成员；指定成员时验证其属于当前家庭。

只开放 `list_passbooks`，内部固定调用 `GET /passbooks`，不提供存折创建、编辑、删除工具或任意接口代理。工具标记 `readOnlyHint=true`、`destructiveHint=false`；用户要求修改或删除存折时，应说明MCP不支持，不得借其他工具绕过。既有Java存折管理功能不因此移除，当前后端admin账号也不是全局只读账号；只读限制指本MCP的存折工具能力。

可按存款日起止日期（YYYY-MM-DD，含首尾）筛选，按存款日或到期日升降序排序，分页每页1至100条。日期筛选不是到期日筛选，银行字段目前仅展示，没有银行筛选参数。返回成员、银行、本金、存款日、年限、利率、到期日、总利息、本息合计和备注。

`total_principal`、`total_amount` 使用后端对全部符合筛选条件存折的合计，不是当前页金额之和。`records` 只是当前页，应结合 `total`、`has_more` 继续翻页，不能以一页明细做全量成员或银行分析。金额及利率以精确小数字符串返回，不经过二进制浮点中转；不按利率重新推算利息或声称本息为当前可用余额。

第一版固定绑定一个账号。普通成员自动使用所属家庭；使用超级管理员（例如 `admin`）时，必须在服务端设置 `FAMILY_ID`，每次认证请求发送固定的 `X-Family-Id`，且校验当前身份返回的家庭与配置一致。工具参数不能切换家庭、指定账号或任意接口地址。

`FAMILY_DEFAULT_MEMBER_ID` 指定默认记账和任务成员；普通成员未配置时默认本人，管理员未配置时必须明确选择成员。成员必须由后端当前家庭成员列表验证。凭证仅从服务端配置读取，账号查询和写入权限沿用现有规则；管理员在固定家庭内具有管理员权限，普通成员能查询全家任务不代表能完成别人的任务。

**MCP 本身不认证微信发送者。** Hermes 对同一实例的其他聊天也可能暴露这些工具，因此正式启用前，应在现有个人微信接入侧限制授权私聊发送者，并核实其他入口、群聊和会话都不能触发该账号的工具。不要将对话里模型提供的微信 ID 当成身份凭据。若需多个家庭成员分别使用，须增加可信身份映射，或为每个授权账号配置隔离实例与凭证；当前版本不提供此能力。

## 本地安装与验证（PowerShell）

在仓库根目录执行：

```powershell
py -3.12 -m venv mcp-server/.venv
mcp-server/.venv/Scripts/python.exe -m pip install -e './mcp-server[test]'
mcp-server/.venv/Scripts/python.exe -m pytest -c mcp-server/pyproject.toml mcp-server/test -q
```

测试均在 `test/`；使用模拟后端和本机临时 HTTP 服务，协议测试由官方 MCP 客户端启动实际 stdio 子进程，不连接生产系统。

## Linux 服务器安装

把本目录复制到 `/opt/family-admin-mcp`，使用独立虚拟环境，避免修改 Hermes 的依赖。下面命令在该目录执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .
umask 077
cp .env.example .env
mkdir -p state
chmod 700 state
chmod 600 .env
```

由管理员在服务器直接填写 `.env` 的账号、密码和后端地址；如使用 admin，还须填写固定家庭和默认成员。不把密码发到聊天或提交到 Git。密码包含特殊字符时使用 dotenv 引号规则。不要将 JWT 写入配置；服务登录后仅在内存保存 Token，收到401或403时最多重新登录一次（现有后端 JWT 过期也可能返回403）。

本次用户指定 `admin`，固定家庭“成家”、默认成员 `zc`。2026-10-24 已通过服务器只读查询确认对应 `FAMILY_ID=1`、`FAMILY_DEFAULT_MEMBER_ID=2`；这属于该服务器的当前配置，其他环境必须重新核对，示例环境文件不自动填入这些编号。

地址要从 **Hermes/MCP 实际运行的网络环境** 可达：示例 `127.0.0.1:8080` 仅适用于宿主机该端口有服务的情况。若后端仅在 Docker 网络内，使用现有本机 Nginx 的正确 `/api` 地址，或把 MCP 放到可访问后端的环境；不要为了此功能直接暴露数据库或后端端口。公网访问使用 HTTPS，明文 HTTP 仅用于可信内网/回环链路。客户端不跟随 HTTP 重定向，不读取代理环境变量。

后端须已经部署收支接口及每日任务接口，并完成 V3 迁移。缺少每日任务接口时，对应工具会明确报错，安装 MCP 不会自动发布 Java 后端或迁移生产数据库。

### 接入 Hermes

1. 备份 Hermes 实际运行账号的 `~/.hermes/config.yaml`。
2. 将 `hermes-config.example.yaml` 的 `family-admin` 条目合并到现有 `mcp_servers`，并在 `platform_toolsets.weixin` 保留 `hermes-weixin`、加入 `mcp-family-admin`，不要覆盖其他平台或微信连接设置。凭证放在 MCP 的 `.env`，不要放进工具参数。
3. 保证 Hermes 运行账号可执行上述 Python，并能读取 `.env` 和读写持久化 `state` 目录。
4. 在该账号和同一 Hermes profile 下执行 `hermes mcp test family-admin`，检查12个工具的发现结果。具体命令以服务器 `hermes mcp --help` 为准。
5. 按当前 Hermes 服务的管理方式重启网关或重新加载 MCP，确保处理微信消息的进程实际加载配置。只启动新的终端会话不代表原微信网关已更新。
6. 先通过授权私聊调用 `get_family_context`，核对账号和家庭，再做一次明确标记的测试记账/任务并在桌面端核对。清理生产测试数据必须有用户明确授权；不对真实账目或任务做自动删除测试。

该 MCP 由 Hermes 作为子进程启动，无需单独 systemd 服务。停用时移除该配置条目并重新加载网关；保留 `.env` 和状态库以便恢复，勿清空状态库后重放历史消息。

## 重试、防重与结果不确定

每个写入调用都必须传 `request_id`，使用来源消息的稳定编号和操作序号，例如 `wechat:message-123:0`。一条消息里的多笔支出使用不同序号；重试同一操作必须沿用编号。同一编号用于不同内容会被拒绝。

SQLite 在发送请求前原子记录状态，保存成功后存储回执。相同编号重复请求返回之前的保存回执，**它代表原操作已保存，不保证记录后来没有被修改或删除**。可明确证明未受理的后端拒绝会释放编号；网络超时、5xx、异常回执以及进程中断后保留待核实状态，阻止自动再次写入。

遇到待核实：先查询相应日期的账目或任务，核对内容、成员与时间。不要换新编号直接重试。如果人工确认未保存，由运维备份状态库后，对该账号作用域内的具体 pending 行进行处理；不要清空全部状态。本版采用保守阻断，不自动猜测是否写入成功。

防重仅覆盖同一持久化状态库、相同账号/家庭/后端地址和相同编号，不是业务数据库级的 exactly-once。模型换编号、其他客户端重复录入、改变后端地址或丢失状态库仍可能重复。若微信插件无法向 Hermes 提供稳定消息编号，必须先在接入侧补齐，不能声称已解决消息重投导致的重复记账。

状态库中包含已保存回执及个人业务数据，应像账号配置一样限制访问并备份。不要把 stdout 用于调试输出，它用于 MCP 协议；诊断输出仅进入 stderr。
