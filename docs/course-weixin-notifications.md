# 课程微信提醒

## 行为

- 收件人为明确配置的 zc 和 xi；每位收件人对应独立的 Hermes profile 默认微信会话。
- 每分钟检查一次，进入开课前 30 分钟窗口时生成提醒；每个课次每位收件人只生成一条。调度延迟时可在开课前补发，已开始的课程不发。
- 提前请假或已有上课记录的课次不发上课前提醒。排队后才请假、删除课程或停用账号时，发送前再次校验并取消。课程延后则延后任务且不消耗网络重试次数。
- 现有自动记课事务成功返回后生成扣课通知，内容包括刚完成的课程，以及当前家庭全部成员的课程余额，含篮球等没有固定课表的独立余额科目。
- 不做课时不足提醒。手工记课不额外触发通知；原有余额未设置、实际没有扣减的自动记录不声称扣课成功。
- 发送失败不回滚扣课。进程在扣课提交和通知生成之间退出时，分钟扫描按记录补偿。只有启用时点之后产生的自动扣课记录进入补偿范围，旧数据不补发。

## 轻量与权限边界

复用现有 JVM 和两个 Hermes 网关；一个有界工作线程处理生成和发送，前一批未结束时不会积压新批次。单轮最多发送 10 条，HTTP 连接超时 2 秒、请求超时 3 秒。暂时失败采用 1、2、4、8 分钟退避，默认最多尝试 5 次；失败状态和错误分类落库。

发送状态使用两分钟租约，进程重启后可以恢复；旧工作线程不能覆盖新领取者的结果。数据库唯一键与稳定的 X-Request-ID 共同防重，网络超时或 Hermes 重启时不承诺跨系统 exactly-once。

任务固定记录家庭、收件用户和通道别名；生成及发送前都校验家庭和账号仍有效。HTTP 请求不能指定其他收件人。Webhook 使用 HMAC V2 时间戳签名，只绑定 Docker 宿主机网桥地址，不新增公网端口、不调用大模型。

当前部署只有一个家庭、4 条课表，课程与余额查询每次最多处理 200 项；超过上限记录错误，不截断后冒充全量。通知表目前不自动清理，预计当前家庭规模增长很小。

## 上线顺序

1. 备份原后端 JAR、两个 Hermes config.yaml 和原外部通知配置；本功能不新建容器。
2. 合并 `deploy/hermes-course-notifications.example.yml` 到两个 profile，分别使用 8644、8645 和独立随机密钥。保留原 MCP、微信凭证、会话、默认收件人和其他配置。
3. 重启原有 `hermes-gateway.service`、`hermes-gateway-weixin2.service`，先只读核对内部监听及 `/health`，不得用未授权用户测试收件。
4. 将 `deploy/course-notifications.example.yml` 填写后复制到原后端容器 `/app/config/course-notifications.yml`，权限限制为运行账号可读。填入实际启用时间与两套一致的密钥，再设 `enabled: true`。密钥不得提交 Git 或输出到日志。
5. 原容器替换 JAR 后重启，Flyway 执行 V14 新建通知表。原上课记录、课时快照及余额不迁移、不回填。
6. 验证容器 ID、JAR 哈希、V14、固定收件配置和任务状态。真实微信验证应使用双方明确授权的测试消息或真实到期提醒，不能伪造生产上课记录来触发扣课。

若需停用，外部配置设 `enabled: false` 并重启原容器；原自动扣课继续工作，通知队列保留。回滚旧 JAR 时保留新增表及已成功的 Flyway 历史，不自动删列、删表或清空任务。

## 验证记录

开发验证使用独立本地临时 MySQL 和本地 HTTP 模拟服务，不连接生产数据库、不向微信发测试消息。具体结果在实施计划中记录，配置模板默认不启用。
