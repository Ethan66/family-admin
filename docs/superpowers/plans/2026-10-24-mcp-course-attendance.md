# MCP 课程记录实施计划

**目标**：基于最新提交 `14fcc62` 的课程功能，通过微信/Hermes记录“已上课”“已请假”，并能查询课程表和课程记录。

**设计**：只增加MCP适配，不改Java、数据库和桌面端。新增 `list_courses`、`record_course_attendance`、`list_course_records` 三工具，复用 `/courses`、`/courses/{id}/attendance`、`/courses/records`。沿用固定账号/家庭/默认成员；课程查询默认配置成员（当前zc），可明确指定家庭内其他成员。MCP升级到0.4.0。

## 已核对的业务规则

- `/courses` 返回本周的课程安排（周一至周日），不能当作任意历史周课程状态。
- 写入状态仅 `ATTENDED` 和 `LEAVE`；日期为今天或过去，必须与课程星期匹配，备注最多500字。
- 一个课程与日期只有一条出勤记录，再提交更新状态和备注；改变已有状态前应说明并确认。
- 已配置课时余额时，首次已上课扣1课时，请假不扣；已上课改请假返还1课时。余额由后端事务维护，MCP不能另行扣减或凭空声称某个剩余数值。
- 写权限及历史记录归属由现有后端校验，不因MCP可查询全家就扩大权限。
- 课程记录接口每页20条，可按成员、课程名称、状态和月份过滤；工具返回分页信息，不把一页当作完整历史。
- 不新增课程定义、删除课程、编辑课时余额、提前为未来课程请假或主动微信提醒。

## 边界与用户例句

### 默认成员更正（0.4.1）

用户明确课程主要查询han，课程专用默认配置为 `FAMILY_COURSE_DEFAULT_MEMBER_ID=4`，通用 `FAMILY_DEFAULT_MEMBER_ID=2` 仍为zc。上下文返回两个默认成员；课程表/历史查询自动选择课程默认成员，显式成员参数优先；未配置课程专用成员时兼容原通用默认。支出/任务默认不变。15项相关配置、上下文、课程默认/显式覆盖和隔离测试通过，未扩大到无关全量验证。

- “今天的钢琴课已上课”：先查默认成员的课表，选定唯一课程，再提交当天已上课记录。
- “昨天的英语课请假了”：查课程安排，确认星期与成员，再补记昨日已请假；不能将本周返回的status当作昨日状态。
- “明天钢琴课请假”：现有后端不允许未来日期，应明确说明未保存，不能擅自改日期或声称记录成功。
- 同名多节课程先按时间/成员选择，不新增课程来消除歧义；同一消息重试必须沿用请求编号。
