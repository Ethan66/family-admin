# 课程微信提醒实施计划

**Goal:** 复用现有 Java 后端定时调度和两个 Hermes 微信网关，向 zc、xi 推送课程提醒，不新增容器。

**已确认规则：** 上课前 30 分钟提醒；自动记课事务成功后推送扣课结果及当前家庭全部课程余额（含独立余额科目），按成员分组。zc 和 xi 都接收。不实现课时不足阈值提醒（用户已明确取消）。

**Architecture:** 通知任务落库去重；生成与网络发送分离。现有自动记课任务在事务返回成功后生成通知，分钟扫描补偿已提交但尚未生成的通知。单个独立工作线程每分钟检查上课窗口、补偿及有界重试，不阻塞扣课或原调度。Hermes 使用带 HMAC V2 签名的 deliver_only Webhook，不调用大模型。

## 文件与步骤

1. `server/src/main/java/com/ethan/familyadmin/notification/`：配置、显式列 Mapper、通知实体、生成服务、发送器、分钟任务。
2. `server/src/main/resources/db/migration/V14__course_notifications.sql`：持久化任务、唯一去重键、待发送索引、重试租约及数据库维护的影子时间字段。
3. `CourseAutoAttendanceJob`：仅在 worker 的事务成功返回后生成扣课通知；通知失败不改变自动记课检查点，分钟扫描补偿。
4. `server/src/test/java/com/ethan/familyadmin/notification/`：先写行为回归，再验证时间窗口、请假/已上课排除、两位收件人、全科余额、防重、签名、重试及崩溃恢复。
5. 本地临时 MySQL 验证迁移、唯一键、并发领取与显式列映射；不写生产测试课次或账目。
6. 配置模板和操作说明：两个 Hermes home 各绑定固定默认微信会话，使用不同内网端口和签名密钥；Java 外部配置指定收件用户与目标，不允许请求参数切换收件人。

## 边界

- 通知默认关闭，启用需明确启用时间，旧自动记录不补发。上课提醒只在开课前的 30 分钟窗口生成，已请假或已记课不发送。
- 每个事件、每个收件人只生成一条任务；网络重试沿用相同请求编号。网关重启或极端网络故障不承诺跨系统 exactly-once。
- 失败最多 5 次，过期上课提醒停止重试；持久化失败状态，不无限重试。
- 发送前复核收件人仍属该家庭且账号有效；课程删除、变更或请假时取消/延后未发送提醒。
- 新功能不改前端、MCP 工具或原扣课规则，不开放公网通知端口。
