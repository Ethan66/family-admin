# 家庭管理 MCP 实施计划

**目标**：通过 Hermes 的 MCP 工具复用现有收支与每日任务接口，不修改 Java、桌面端或数据库结构。

**架构**：独立 Python 3.11+ stdio 服务，官方 MCP Python SDK 1.x、HTTPX、SQLite。固定账号从进程环境读取；用户选择 `admin`，通过服务端 `FAMILY_ID` 固定“成家”，`FAMILY_DEFAULT_MEMBER_ID` 默认 `zc`。仅通过现有 REST 接口操作数据，后端继续校验权限。第一版面向单个可信私聊身份，不把模型填写的微信 ID 当作授权证据。

**已确认的需求**：用户已同意 MCP 方案并要求在提交、推送现有代码后开始开发。当前代码快照为 `1d9ed35`，已推送 `origin/v_1.0`。本次新增实现留在当前分支供验收，不自动提交新实现。

## 边界

- 不新增微信接入，不实现多微信账号自动映射，不开放群聊共用固定账号。
- 除用户追加授权的任务删除和支出删除外，不增加其他删除、任意接口调用、SQL、文件访问工具，不开放公共 MCP HTTP 端口。
- 本地 SQLite 是单个 MCP 状态库范围内的保守防重，不宣称后端跨客户端 exactly-once。不同请求编号仍可能重复，需要 Hermes 沿用同一来源消息的操作编号。
- 主动微信提醒另做；创建带时间的任务不等于提醒。
- 服务器正式启用前须填写用户指定账号凭证，并确认现有个人微信接入只允许授权私聊；不读取或打印未授权账号凭证。
