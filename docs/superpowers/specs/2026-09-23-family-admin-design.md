# 家庭管理后台设计方案

## 1. 背景与目标

基于当前 `产品文档/` 中的静态交互原型，开发一套可实际部署的前后端分离家庭管理系统。系统面向多个家庭，一个家庭对应一个租户，家庭之间的数据严格隔离；超级管理员可以管理全部家庭，并查看各家庭的数据。

首版目标：

- 落地现有原型中的登录、家庭概览、收支、试卷、照片、影片和学习笔记模块。
- 增加超级管理员使用的家庭与成员账号管理能力。
- 增加个人资料与修改密码能力。
- 将浏览器本地数据替换为 Java 后端、MySQL 和受权限保护的本机文件存储。
- 保留原型的整体信息架构、桌面端布局和窄屏适配方向。

## 2. 范围

### 2.1 首版包含

- 账号密码登录、退出、当前用户信息、修改密码。
- 超级管理员管理家庭、家庭成员账号、账号状态和家庭内角色。
- 家庭概览统计。
- 收入支出增删改查、月份/类型/分类筛选及汇总。
- 试卷增删改查、批改、科目/年级/状态筛选及统计。
- 照片上传、列表、相册/月份筛选、预览和删除。
- 影片信息与封面增删改查、类型/状态筛选和观看进度维护。
- 学习笔记列表、标签筛选、搜索、Markdown 预览和删除。
- 登录、用户停用、角色调整、跨家庭查看、删除操作的审计日志。

### 2.2 首版不包含

- 学习笔记新增和编辑。
- 视频文件上传与在线播放。
- 家庭用户侧的成员管理页面。
- 预算、账单导入导出、消息提醒、第三方登录。
- MinIO、OSS 等远程对象存储。
- 微服务拆分。

## 3. 项目结构与技术栈

```text
family-admin/
├─ web/                Vue 3 前端
├─ server/             Spring Boot 后端
├─ storage/            本机文件存储目录
├─ deploy/             数据库与部署配置
├─ docs/               需求、设计和实施文档
└─ 产品文档/           原始产品原型，保留不覆盖
```

前端：

- Vue 3、TypeScript、Vite。
- Element Plus、UnoCSS。
- Vue Router、Pinia、Axios。
- Vitest 与 Vue Test Utils。

后端：

- Java 21、Spring Boot 3。
- Spring Security、JWT。
- MyBatis-Plus、MySQL。
- Flyway 管理数据库结构。
- JUnit 5、Mockito，接口测试使用 Spring MVC Test。

架构采用前后端分离的模块化单体。它比微服务更适合首版规模，又能通过明确的模块边界支持后续拆分。

## 4. 用户、租户与权限

系统角色：

| 角色 | 权限 |
| --- | --- |
| 超级管理员 | 管理所有家庭和账号；选择目标家庭查看全部业务数据 |
| 家庭管理员 | 查看并管理本家庭全部业务数据；不能管理成员账号 |
| 普通成员 | 查看本家庭全部业务数据；只能修改或删除自己创建的记录 |

核心约束：

- 一个家庭对应一个租户，业务表全部包含 `family_id`。
- 每个非超级管理员账号首版只能归属一个家庭；超级管理员不归属具体家庭。
- 家庭用户请求中的家庭上下文来自认证信息，不能通过请求参数任意切换。
- 超级管理员使用专用管理接口显式选择目标家庭；跨家庭业务数据首版只读，不代替家庭用户修改业务记录。
- 前端路由和按钮权限只改善交互体验，最终权限以后端校验为准。
- 查询、详情、更新、删除、文件访问都必须校验租户和角色，不能只在列表查询时过滤。
- 用户停用后不能继续登录；令牌中的用户状态需要在服务端再次校验。

## 5. 页面设计

### 5.1 家庭用户页面

- 登录页。
- 家庭概览。
- 收入支出。
- 试卷管理。
- 照片管理。
- 影片管理。
- 学习笔记：只提供列表、搜索/筛选、预览、删除。
- 个人资料与修改密码。

### 5.2 超级管理员页面

- 家庭列表与家庭新增、编辑、启用、停用。
- 家庭详情：维护该家庭的成员账号、家庭内角色和账号状态。
- 全局数据查看：选择家庭后进入对应业务数据视图。
- 审计日志查询。

所有列表页面都必须具备加载、空数据、错误、重试状态。提交操作必须防重复提交，删除操作必须二次确认。

学习笔记首版不提供任何新增入口。开发环境可使用示例数据验证列表和预览；生产环境没有既有笔记时展示空状态，数据导入不在首版范围内。

## 6. 后端模块与接口

模块边界：

- `auth`：认证、当前用户和密码管理。
- `family`：家庭租户和成员账号管理。
- `dashboard`：概览聚合统计。
- `transaction`：家庭收支。
- `exam`：试卷与成绩。
- `photo`：照片元数据和图片文件。
- `movie`：影片、封面与观看进度。
- `note`：学习笔记只读查询与删除。
- `file`：文件保存、读取和删除标记。
- `audit`：关键操作日志。

接口前缀：

```text
/api/auth/*
/api/dashboard/*
/api/transactions/*
/api/exams/*
/api/photos/*
/api/movies/*
/api/notes/*
/api/profile/*
/api/admin/families/*
/api/admin/audit-logs/*
```

响应约定：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {}
}
```

分页数据统一包含 `records`、`total`、`page`、`pageSize`。参数错误、未登录、无权限、资源不存在、业务冲突和系统异常使用稳定错误码，并由统一异常处理器转换为一致响应。

## 7. 数据模型

核心表：

- `family`：家庭名称、状态、备注。
- `user`：登录名、密码摘要、显示名称、状态、超级管理员标记。
- `family_member`：用户、家庭、家庭内角色。
- `transaction_record`：类型、金额、日期、分类、成员、备注。
- `exam_paper`：名称、科目、年级、考试日期、满分、得分、状态、复盘。
- `photo`：标题、相册、拍摄日期、描述、文件引用。
- `movie`：片名、类型、年份、导演/作者、时长、评分、观看状态、进度、简介、封面文件引用。
- `study_note`：标题、标签、Markdown 正文和更新时间。
- `file_object`：原始文件名、存储键、媒体类型、大小、摘要和状态。
- `operation_log`：操作者、家庭、动作、资源、结果、时间和必要上下文。

业务表统一包含主键、`family_id`、创建人、创建时间、更新人、更新时间和逻辑删除标记。金额使用 Java `BigDecimal` 和 MySQL `decimal`，不使用浮点数。

## 8. 文件存储

- 照片保存真实图片，影片只保存封面，不上传视频文件。
- 文件按家庭和日期组织存储，但数据库仅保存不可猜测的存储键，不保存供客户端直接使用的磁盘路径。
- 上传校验扩展名、媒体类型、文件头和大小。
- 预览和下载必须先通过后端租户及权限校验。
- 删除业务记录时先逻辑删除文件元数据；物理文件由清理任务延迟处理。
- 文件存储通过接口抽象，后续可替换为 MinIO 或 OSS。

## 9. 前端架构与数据流

- Router 定义公共、家庭用户和超级管理员路由，并通过路由守卫校验登录态与角色。
- Pinia 只保存登录用户、权限和超级管理员当前选择的家庭上下文。
- 页面筛选、弹窗和临时表单状态保留在页面或 composable 中。
- Axios 统一附带令牌；未登录返回登录页，无权限显示明确提示。
- API 类型、表单类型和展示模型分离，避免页面直接依赖后端原始结构。
- Element Plus 承担表单、表格、弹窗和反馈；UnoCSS 负责布局、间距、响应式和主题补充。
- 保留现有原型的信息层级和视觉语言，但不复制原生 DOM 拼接实现。

## 10. 错误处理与安全

- 密码使用强哈希算法保存，任何接口和日志都不得返回密码摘要。
- JWT 密钥、数据库密码和存储路径通过环境配置注入。
- 登录失败使用统一提示，避免泄露账号是否存在。
- 文件名不参与实际磁盘路径拼接，防止路径穿越。
- 对分页大小、上传大小、文本长度、金额和日期范围设置上限。
- 关键写操作记录审计日志，但不记录密码、令牌或文件内容。
- 数据库唯一约束和事务保证家庭、账号及业务写入的一致性。

## 11. 测试与验收

后端重点验证：

- 家庭之间的列表、详情、更新、删除和文件访问均不可越权。
- 超级管理员可以选择并查看目标家庭数据。
- 家庭管理员与普通成员的写权限符合规则。
- 金额汇总、试卷统计、观看进度和逻辑删除正确。
- 上传格式、文件头、大小和非法路径被拒绝。
- 用户停用、密码修改和令牌失效逻辑正确。

前端重点验证：

- 不同角色的路由、菜单和按钮正确显示。
- 表单校验、防重复提交、删除确认正确。
- 列表筛选、分页、加载、空态、错误和重试状态完整。
- 照片上传预览、影片封面、Markdown 预览正确。
- 桌面端和窄屏布局可用。

交付前执行前端类型检查、单元测试和构建，以及后端单元测试和打包；启动开发环境后逐页与 `产品文档/` 原型核对。

## 12. 实施约束

- 首版在一个仓库内维护 `web/` 与 `server/`。
- 先建立认证、租户隔离和权限基础，再实现业务模块。
- 每个模块按接口契约、测试、实现、页面和联调的顺序完成。
- 不为未确认的未来功能提前引入微服务、消息队列或复杂基础设施。
