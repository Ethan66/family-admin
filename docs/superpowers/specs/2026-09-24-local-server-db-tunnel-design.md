# 本地后端数据库隧道启动脚本设计

## 目标

在 Windows 本地开发环境中，通过一个 PowerShell 脚本完成以下操作：

1. 建立到 `root@8.153.99.32` 的后台 SSH 隧道。
2. 将本地 `127.0.0.1:3307` 转发到服务器 `127.0.0.1:3307`，再由服务器 Docker 映射到 MySQL 容器的 `3306`。
3. 使用脚本内固定配置设置本次进程所需的后端数据库环境变量。
4. 使用项目自带的 Maven Wrapper 启动本地后端。
5. 后端退出后，清理本次脚本创建的 SSH 隧道进程。

## 文件与入口

- 在项目根目录新增 `start.ps1`。
- 开发者在项目根目录执行 `./start.ps1`。
- SSH 目标固定为 `root@8.153.99.32`，不额外创建配置文件，也不修改 `.gitignore`。

## 启动流程

1. 检查本机 `3307` 端口是否已可连接。
2. 如果端口已可连接，复用现有隧道，不重复启动 SSH 进程。
3. 如果端口不可连接，以隐藏窗口启动 `ssh.exe`，启用转发失败即退出和连接保活选项。
4. 在有限时间内轮询 `127.0.0.1:3307`；连接失败时给出明确错误并停止后续启动。
5. 设置：
   - `DB_URL=jdbc:mysql://127.0.0.1:3307/family_admin?...`
   - `DB_USERNAME=family_admin`
   - `DB_PASSWORD` 使用脚本内固定的 MySQL 密码，不再运行时提示输入。
6. 在 `server` 目录运行 `mvnw.cmd spring-boot:run`。
7. 脚本结束时，只停止自己创建的 SSH 进程；复用的既有隧道不处理。

## 安全与错误处理

- 不把 SSH 密码或私钥内容写入脚本。
- 根据用户明确选择，MySQL 密码以明文固定在本地脚本中；设计文档不重复记录具体密码值。
- 后台 SSH 依赖密钥登录；如果仍需交互式 SSH 密码，隐藏进程无法完成登录，脚本会在端口检查阶段报错。
- 数据库密码会存在于项目脚本文件、当前脚本进程及其后端子进程环境中。
- 检查 `ssh.exe`、`server/mvnw.cmd` 是否存在，缺失时立即给出错误。
- 不终止无法确认归属的 SSH 进程。

## 验收标准

1. SSH 密钥可用时，执行一次脚本即可启动隧道和本地后端。
2. 本地 `3307` 已被可用隧道监听时，不产生重复 SSH 进程。
3. 隧道建立失败时，不启动后端，并显示可理解的错误。
4. 脚本无需输入 MySQL 密码即可设置 `DB_PASSWORD`。
5. 后端可通过 `127.0.0.1:3307` 完成 Flyway 初始化并连接服务器 MySQL。
6. 后端退出后，本次创建的隧道被清理。

## 变更记录

### 2026-09-24 固定 MySQL 密码

**变更原因**：用户希望启动后端时不再输入 MySQL 密码，并明确接受密码以明文保存在项目脚本中的风险。

**影响范围**：`start.ps1` 的数据库环境变量设置，以及对应契约测试。

### 2026-09-24 修正服务器 MySQL 映射端口

**变更原因**：服务器 Docker 实际使用 `0.0.0.0:3307 -> 3306/tcp`，服务器宿主机的 `3306` 没有服务监听。

**影响范围**：将 SSH 转发目标从服务器 `127.0.0.1:3306` 修正为 `127.0.0.1:3307`。

- 删除运行时安全输入 MySQL 密码的逻辑。
- 在脚本内固定设置 `DB_PASSWORD`。
- 密码具体值只保留在实现脚本中，不复制到设计或计划文档。
